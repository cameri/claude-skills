<objective>
Writes Audiobookshelf credentials to `~/.claude/channels/audiobookshelf/{env}.env` and verifies the connection. Uses an Audiobookshelf API key (created in the web UI under **Settings → Users → \<user\> → API Keys**), sent as a Bearer token.
</objective>

<quick_start>
Save: `/audiobookshelf:access url=<URL> key=<API_KEY>`

Check status: `/audiobookshelf:access` (no args)

Guided setup: `/audiobookshelf:access setup`
</quick_start>

<context>
Parse `env=<name>` from `$ARGUMENTS` before any other processing. Strip it from remaining arguments. Default to `""` (empty string). Display empty ENV as "(default)". Credential file: `~/.claude/channels/audiobookshelf/${ENV}.env`. Omit `env=` from suggested commands when ENV is empty.
</context>

<credential_format>
`~/.claude/channels/audiobookshelf/${ENV}.env`:

```
AUDIOBOOKSHELF_URL=https://your-instance.example.com
AUDIOBOOKSHELF_API_KEY=your-api-key
```

Single-quote values containing special characters. `chmod 600` after writing.
</credential_format>

<workflow>
**No args — status and guidance:**

Read `~/.claude/channels/audiobookshelf/${ENV}.env` (missing = not configured) and show:

1. **Environment** — active environment name, or "(default)" if ENV is empty.
2. **Server URL** — `AUDIOBOOKSHELF_URL`: show value, or "not set".
3. **API key** — if `AUDIOBOOKSHELF_API_KEY` set: "set (masked, first 4 chars + ...)"; otherwise: "not configured". Never print the full key.
4. **Connection test** — if URL and key present:
   ```
   http --ignore-stdin -b GET "${AUDIOBOOKSHELF_URL%/}/api/me" "Authorization:Bearer $AUDIOBOOKSHELF_API_KEY"
   ```
   - Success (returns a JSON object with an `id`/`username`): show "✓ Connection OK" plus the `username` and `type` (e.g. `root`) fields.
   - Failure (401/403 or connection error): show the error and suggest checking the URL or generating a fresh key.
5. **What next** — concrete next step:
   - No file or missing URL/key → show setup command syntax and ask for values.
   - Configured but connection failed → *"Run `/audiobookshelf:access` again after correcting the failing credential."*
   - All set, connection OK → *"Ready. You can now use `/audiobookshelf:query-library`."*
6. **Available environments** — list all `*.env` files in `~/.claude/channels/audiobookshelf/`, stripping `.env` suffix. Display `.env` as "(default)".

**`setup` — guided setup:**

1. Explain each credential:
   - **AUDIOBOOKSHELF_URL**: Base URL of the Audiobookshelf instance (e.g. `https://books.example.com`).
   - **AUDIOBOOKSHELF_API_KEY**: Generated in the web UI under **Settings → Users → \<user\> → API Keys → New API Key**. Ties to that user's permissions (a `root`-type user's key can access all libraries; a limited user's key is scoped to what that user can see).
2. Ask user to run the explicit form once they have values (omit `env=` for default):
   ```
   /audiobookshelf:access url=<URL> key=<API_KEY>
   ```

**Explicit save — `url=<URL> key=<API_KEY>`:**

Parse key=value pairs. Accept both `key=`/`url=` and `AUDIOBOOKSHELF_API_KEY=`/`AUDIOBOOKSHELF_URL=` forms (strip `AUDIOBOOKSHELF_` prefix if present, case-insensitive).

Required: both `url` and `key`. List absent keys and stop if missing.

1. `mkdir -p ~/.claude/channels/audiobookshelf`
2. Read existing `${ENV}.env` if present; update/add provided keys, preserve others.
3. Strip trailing slash from `AUDIOBOOKSHELF_URL` before writing.
4. Write back as `KEY='value'` (single-quoted for special characters).
5. `chmod 600 ~/.claude/channels/audiobookshelf/${ENV}.env`
6. Test the connection (same as status check).
7. Show result and full status.

**`clear` — remove all credentials for this environment:**

Delete `~/.claude/channels/audiobookshelf/${ENV}.env`. Confirm first: *"This will remove all Audiobookshelf credentials for the selected environment. Are you sure?"*

**`clear <key>` — remove a single credential:**

Remove only the named key line from `${ENV}.env`. Valid keys: `url`, `key`.
</workflow>

<security_checklist>
- Never log or display the full `AUDIOBOOKSHELF_API_KEY` — show only first 4 chars + `...`
- Always `chmod 600` the `.env` file after writing
- Always strip trailing slashes from `AUDIOBOOKSHELF_URL`
- API keys are tied to a specific user's permissions — a key generated by a limited (non-root) user only sees what that user can see
- If the connection test returns a TLS error, suggest checking `http://` vs `https://` and certificate validity
</security_checklist>

<success_criteria>
- Credentials written to `~/.claude/channels/audiobookshelf/${ENV}.env` with `chmod 600`
- Connection test passes (`/api/me` returns a valid user object)
- Status output never exposes the full API key
- User knows exactly what to do next based on current state
</success_criteria>
